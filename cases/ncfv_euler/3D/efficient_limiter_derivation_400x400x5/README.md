## 1. 共享梯度的完整贡献与预算

恢复点和面侧均值必须分别列为约束：

\[
P_i=\bar U_i-\sum_j G_j^T R_{ij},\qquad
M_{if}=\bar U_i+\sum_jG_j^T(W_{ifj}/A_f-R_{ij}).
\]

对冻结原始梯度令 \(c_{aj}=G_j^{H,T}b_{aj}\)，其中 \(b\) 必须使用上述完整权重。最终共享梯度为 \(\theta_jG_j^H\)。逐约束、逐守恒分量计算

\[
P_a=\sum_j\max(c_{aj},0),\quad N_a=\sum_j\max(-c_{aj},0),\quad
\tau_a=\min(1,(U_{max,a}-\bar U_i)/P_a,(\bar U_i-U_{min,a})/N_a),
\]

省略绝对值不超过 10⁻¹⁰ 的分母项，再将该约束的共同系数归并到所有参与节点：\(\theta_j=\min_{a:j\in S_a}\tau_a\)。分量取最小值，最终每个节点对全部分量仍共用一个系数。

正负贡献分别受限后，任意节点进一步缩小系数都不会破坏这些线性预算。代价是丢失部分有益抵消，可能增加耗散。这里不复用原来的顺序乘积判据。

保正另外考虑整个盒子 \([\bar U-\tau N,\bar U+\tau P]\)：取最小密度、最小总能量以及各动量最大绝对值构造压力下界；必要时二分缩小 \(\tau\)。这样独立缩小节点系数仍保持正性。该方案不宣称满足压力极值上界，也不宣称保证完整时间更新有界。

所有系数确定后才恢复点值、计算链式通量导数；不增加运行时高阶积分点或黎曼调用。

## 2. 完整通量限制

令高效算法的完整面通量为 \(H_f\)，LLF 低阶通量为 \(L_f\)，采用

\[
F_f=L_f+\alpha_f(H_f-L_f),\qquad0\le\alpha_f\le1.
\]

取 \(\eta_f=a_fA_f\) 和低阶辅助状态 \(B_f\)，同时限制

\[
B_f-\alpha_f(H_f-L_f)/\eta_f,\qquad
B_f+\alpha_f(H_f-L_f)/\eta_f.
\]

约束包括局部守恒分量范围（同时包含合法低阶辅助状态）、正密度、正压力、压力下限与 \(p/\rho^\gamma\) 下限。后者对应凸可行域 \(E-\|m\|^2/(2\rho)-s_{min}\rho^\gamma/(\gamma-1)\ge0\)。不施加非凸的压力上界。

连续方案在线性界限后对压力／比熵判据二分。二元方案仅在全部判据允许完整修正时保留高阶，否则取零；计算出的通量仍由面 owner 唯一计算并共享。

每个 SSPRK 子阶段检查实际 \(\Delta t\sum_f\eta_f/V_i\le1\)。保正依赖合法的低阶辅助状态、几何闭合、边界及该 CFL 条件；代码会显式报错，不能把步重试等同于理论保证。完整通量限制不重新执行高阶积分或链式求导，额外成本是低阶通量、辅助状态约束、触发面上的二分及节点界限交换。

## 3. 共享系数 QP：仅作小网格参考

\[
\min_{0\le\theta\le1}\frac12\sum_j(\theta_j-1)^2,
\qquad U_{min,a}\le\bar U_i+\sum_jc_{aj}\theta_j\le U_{max,a}.
\]

`qp_reference.py` 对实际三维周期网格的冻结算子选取 80 个未知量，固定其他系数为零，保留全部受影响的完整支持约束。该诊断有 9345 条非零标量约束；光滑状态中 QP 平均 θ≈0.82839，预算≈0.71978，最大违例约 2.78×10⁻¹⁷。这说明联合分配能保留更多抵消，但并不构成 RP1 时间推进或全局优化证据。QP 未加入非线性压力约束，仅事后检查正性；不用于本轮 80 万节点的生产计算。

## 追加对照：LLF_FIRST_ORDER

用户要求再增加一个算例后，追加纯一阶 LLF 对照，保持 RP1、400×400×5、Δz=0.01、128 个独立物理核及 t=0.25。它令完整高阶通量修正的上限为零，因此内部和外推边界的实际通量均只由守恒体均值构造。没有改动或重新编译原四组使用的冻结可执行文件。

该算例用于判断没有高阶通路时的振荡与二维保持性，不是新限制器。冻结程序仍计算未用于最终通量的高阶候选，故其耗时不能视作专用一阶程序的最小成本。

`run_additional_case.py` 先执行 40×40×5、4 进程的 t=0.25 检查，验证开关、正性与独立节点身份；通过后排队。原四组优先，只有当原队列无待启动任务，且一整组 128 个物理核已释放时才启动追加算例，不共享原作业物理核。原四组状态仍由原控制器管理；追加状态为 `LLF_FIRST_ORDER/run_status.json`。完成后追加控制器生成包括五组结果的统一比较及真实五层切片。

用户已取消随后追加的两组重复复算，其等待控制器、重复配置及未运行目录已删除。当前仅保留原四组与 LLF 对照，共五个大网格算例；取消记录保存在输出根目录的 `cancelled_duplicate_jobs.json`。

## 用户授权的 SMT 并发（2026-10-29）

原队列已由 `run_suite_smt.py` 接管。接管只更换 Python 调度控制器，SG_BJ_PRES、SG_SIGN_BUDGET 的原 MPI 启动器 PID、数值进程、时间步及输出均延续，无重启、无重复作业。已通过全部 512 个进程的实际亲和性检查。

| 算例 | Linux 逻辑 CPU | MPI 进程数 | 物理核关系 |
|---|---|---:|---|
| SG_BJ_PRES | 0–127 | 128 | 与 FC_IDP_BINARY 使用同组物理核的两条硬件线程 |
| SG_SIGN_BUDGET | 128–255 | 128 | 与 FC_IDP_CONT 使用同组物理核的两条硬件线程 |
| FC_IDP_BINARY | 256–383 | 128 | 新启用的 SMT 线程 |
| FC_IDP_CONT | 384–511 | 128 | 新启用的 SMT 线程 |

每个作业内仍覆盖 128 个不同物理核；四组合计是 512 个不同逻辑 CPU、256 个物理核，不能相加称为 512 物理核。不存在两个 MPI 进程绑定同一个逻辑 CPU。SMT 共享执行资源，后续应根据推进速度和总完成时间评估收益。

LLF_FIRST_ORDER 仍排队，在 0–127 或 128–255 释放时自动启动。原先“整组物理核空闲”的排队说明在本次 SMT 授权后调整为检查对应逻辑 CPU 组空闲，允许其物理核的另一条线程同时执行 FC 算例。

接管记录为输出根目录 `smt_controller_handoff.json`；四组无逻辑核重叠的实测证据为 `smt_affinity_validation.json`；各组逐进程证据仍在 `cpu_affinity.json`。原 MPI 启动器被接管后，调度器无法取得其最初父进程保存的退出码，故完工依据明确记录为启动器退出及有效最终检查点达到 t=0.25，不将未知退出码伪记为零。
