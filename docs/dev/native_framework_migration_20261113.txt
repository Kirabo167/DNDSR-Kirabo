2. 与本地原有架构的关系

本地 Geom/CFV 的 tracked legacy mesh、ArrayPair/ArrayDof 和求解器循环
仍为 Euler、ACM、NCFV 的兼容接口，保留既有方程和用户研究修改。
新路径使用原生 EntitySpace、持久实体 ID、Runtime 数组和 Algebra DOF：

  src/NativeGeom (DNDS::NativeGeom)
      -> src/NativeCFV (DNDS::NativeCFV)
      -> src/Physics (DNDS::Physics) / src/Cauchy (DNDS::Cauchy)
      -> Cauchy Domain / Simulation / cauchy.exe

参照版本的 Geom/CFV 迁入独立命名空间，避免覆盖本地研究实现。
Cauchy 的数值路径实际使用新网格和原生字段；旧求解器仍使用原接口。
因此，共享数据层已经更新，但旧求解器不会自动获得 Cauchy 的外层调度。
旧字段可通过显式共享桥接接入；布局变化后必须重新建立依赖该布局的绑定。

原生网格包括实体分布/owner/ghost、邻接注册表、拓扑和几何状态、周期信息、
保留读取作用域、事务编辑、快照、重排/重新分区、细化、边界提取和网格归档。
输入支持 CGNS、OpenFOAM、原生及兼容归档，提供有限体积几何与重构准备。
Cauchy 包括方程块字段、热物性/RANS、有限体积残差和重构、显式/隐式推进、
Krylov/SGS/ILU、非线性迭代、多项式多重网格、多域接口、检查点和结果输出。
导入这些能力不代表所有工程算例精度或收敛性均已验证。

4. 迁移时修复的问题

1) 新旧 CSR 归档统一使用 serializer 的 row-start codec/cache 接口，
   移除旧 transformer 的第二次手工 row-start 写入，避免共享缓存/offset 错误。
2) 原生 JSON 归档逐 rank 打开失败先协调，再进入后续通信，避免单 rank
   解析错误导致其他 rank 等待；HDF5 的 collective open 路径保留。
3) 网格 transition 在启动保留 MPI transfer 前统一获取并检查输入关系。
4) 旧数组 Python buffer 保留 allocation owner；CSR row-start 元数据只读。
5) Runtime Python 包装层、跨扩展测试模块及安装链补齐。
6) ConfigRegistry、ConfigParam、JsonSchema 和 serializer 补齐新框架所需接口；
   Direct solver 增加分阶段 LU/generation，数学工具补齐 SVD/惯性方向能力。
7) 修复上游 Cauchy 的 const 指针推导、输出字段 const 和 RANS 头文件问题；
   无 RANS 时不再请求不存在的 closure。
8) 原生和旧 Geom 的相同 EigenTensor 工具共用一个头文件，避免重复定义。
9) 新导入的两个 C++ 测试改用本地已有 IV10_10.cgns，保留性质和算法对照。
   LimitedVR 保留固定参照实现，作为独立测试 oracle。
10) 墙距 C++ 和 mixed-authority Python 故障测试使用同一个原生私有通信器，
    并保留通信器 owner，避免测试构造本身造成 MPI 等待或悬空。
11) Python 混合气算子用例按实际 Cantera 构建能力跳过；其他异常仍正常失败。

6. CUDA 与可选依赖边界

本阶段支持的 Cauchy Domain/Simulation 前端是 CPU。
CUDA 13.1、sm86、RTX A5000 下，迁入的 CUDA 库及 9 个算子测试可构建。
实际运行 2/9 通过（limited_vr、characteristics），7/9 失败：
point_physics、auxiliary、rhs、source、positivity、gradient、state。
RANS 点核存在 CPU/GPU 数值不一致；state 的 managed/direct halo 路径要求
CUDA-aware MPI，而本机 MPI 不具备该能力；其他失败也不能据此统一归因。
未放宽数值阈值，不能据编译成功宣称 Cauchy GPU 求解器可用。
这些日志保留；DNDS_BUILD_CAUCHY_CUDA_TESTS 默认 OFF，build-cuda 已恢复 OFF。
显式开启该选项可继续诊断；现有 Runtime/Algebra、EulerP CUDA 路径独立。

Cantera 反应流、AmgX、NCCL 不在本阶段已通过的验证范围内。
已有机理文件不等于本次构建启用了 Cantera。CPU 验证不能替代反应流验证。

7. 复现命令（项目根目录，选择与构建匹配的 Python 解释器）

  CC=mpicc CXX=mpicxx cmake -S . -B build \
      -DDNDS_BUILD_TESTS=ON -DDNDS_USE_CANTERA=OFF
  cmake --build build -t all_solvers all_unit_tests all_pybind11 -j16
  cmake --install build --component py
  ctest --test-dir build -LE python --output-on-failure -j8
  ctest --test-dir build -L native --output-on-failure -j8
  PYTHONPATH=python:build/test/cpp mpirun -np 2 \
      /home/mrz/.venvs/DNDSR-Kirabo/bin/python -m pytest \
      test/DNDS test/NativeGeom test/Cauchy -q
  build/app/cauchy.exe cases/cauchy/smoke.json --check-config
  mpirun -np 4 build/app/cauchy.exe cases/cauchy/smoke.json

每次修改相关 C++ 源码，必须重建并安装 Python 扩展后再运行 Python 测试。
新旧接口不能混用网格对象类型；Runtime lease/read scope 必须在修改或推进前释放。
