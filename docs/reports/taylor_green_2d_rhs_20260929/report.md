# 二维不可压缩 Taylor–Green 精确场：NCFV 传统/高效空间算子精度

## 验证范围

本试验比较 NCFV 的 `TraditionalQuadrature` 和 `EfficientDifferential`
对**动量方程瞬时右端项**的空间离散误差。NCFV 目前求解可压缩 Navier–Stokes，
其周期接口只接受三维全周期盒。因此使用已有 `[-π,π]^3` 的
8³、16³、32³、64³、128³、256³ 六面体网格，将二维解析场沿 `z` 方向延拓，且不进行
时间推进。

设 `ν=μ=0.01`、`ρ=1`、`A(t)=exp(-2νt)`，解析场为

\[
u=A\sin x\cos y,\quad
v=-A\cos x\sin y,\quad
w=0,\quad
p=100+\frac{A^2}{4}(\cos 2x+\cos 2y).
\]

它严格满足二维不可压缩 Navier–Stokes 的质量与动量方程，所以在
`t=0` 和 `t=8` 应有 `∂ₜ(ρu,ρv,ρw)=−2ν(u,v,0)` 和 `∂ₜρ=0`。
取常密度解析场构造理想气体守恒状态时，NCFV 的**瞬时质量与动量**连续方程
具有相同的解析右端；可压缩能量方程不满足该解析解。本试验因此不能
验证完整可压缩时间推进的误差或时间收敛阶。

所有算例共用 SVD 最小二乘二次重构、Roe 通量、常黏度、关闭限制器。
解析原始变量按网格节点采样并作为 NCFV 对偶控制体状态输入，故这里的
误差包含这种状态表示误差；不能把测得的阶数单独归因于某个求积公式。

对每个节点的动量右端误差向量 `eᵢ`，以对偶体积 `Vᵢ` 定义
`L₂=[ΣVᵢ|eᵢ|²/ΣVᵢ]^(1/2)`。相邻加密级别的观测阶为
`p=log₂(L₂(N)/L₂(2N))`。原始数值见 [metrics.csv](metrics.csv)，
图见 [convergence.svg](convergence.svg)。

## 结果

| 每方向单元数 | 高效 `L₂`，t=0 | 传统 `L₂`，t=0 | 高效 `L₂`，t=8 | 传统 `L₂`，t=8 |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 0.965238 | 0.633002 | 0.819043 | 0.536399 |
| 16 | 0.143310 | 0.0891174 | 0.121523 | 0.0755371 |
| 32 | 0.0186573 | 0.0114787 | 0.0158155 | 0.00972610 |
| 64 | 0.00234569 | 0.00145430 | 0.00198644 | 0.00122934 |
| 128 | 0.000293014 | 0.000187607 | 0.000247179 | 0.000157147 |
| 256 | 0.0000374551 | 未运行 | 0.0000311363 | 未运行 |

| 加密区间 | 高效观测阶，t=0 | 传统观测阶，t=0 | 高效观测阶，t=8 | 传统观测阶，t=8 |
| --- | ---: | ---: | ---: | ---: |
| 8→16 | 2.752 | 2.828 | 2.753 | 2.828 |
| 16→32 | 2.941 | 2.957 | 2.942 | 2.957 |
| 32→64 | 2.992 | 2.981 | 2.993 | 2.984 |
| 64→128 | 3.001 | 2.955 | 3.007 | 2.968 |
| 128→256 | 2.968 | — | 2.989 | — |

两种方法的误差均以约三阶下降。在 128³、`t=8`，传统方法的动量右端
`L₂` 误差约为高效方法的 `0.636` 倍；相对解析动量时间导数的误差分别是
`1.304%`（传统）和 `2.051%`（高效）。传统方法的误差常数优势在 `t=0` 和
`t=8` 基本相同。128³、`t=8` 时质量方程右端的 `L₂` 误差分别为
`4.73×10⁻⁶`（高效）和 `2.78×10⁻⁶`（传统）。

256³ 高效方法在 `t=0` 和 `t=8` 的相对动量右端 `L₂` 误差分别为
`0.265%` 和 `0.258%`，相应的质量右端 `L₂` 误差分别为
`8.15×10⁻⁷` 和 `5.93×10⁻⁷`。由 128³ 加密到 256³ 时，两个时刻的
动量误差观测阶分别为 `2.968` 和 `2.989`，与前三阶空间收敛趋势一致。

## 复现

```bash
cmake --build build -t ncfv_taylor_green_2d_rhs_probe -j4
venv/bin/python cases/NCFV/diagnostics/run_taylor_green_2d_rhs.py
```

默认脚本使用 `data/mesh/taylor_green/tgv_hex_{8,16,32,64,128}.cgns`，运行
`t=0,8` 的两种积分模式，并写出 CSV、SVG 与每组运行日志。源代码为
`cases/NCFV/diagnostics/taylor_green_2d_rhs_probe.cpp`。数据来源于
[二维 TGV 解析解文献](https://doi.org/10.1063/5.0159551)；实现中压力的
空间常数 `100` 不影响解析动量方程。

256³ 高效方法另以 `--sizes 256 --modes Efficient --times 0 8 --max-rings 2
--ranks 32 --min-available-gib 96 --allow-large --append` 运行，并设置
`OMP_NUM_THREADS=1`、`MALLOC_ARENA_MAX=2`。执行该命令前需确认有足够
空闲内存，运行器会在可用内存低于安全线时终止 MPI 进程。

## 256³ 资源试验

已生成并验证 `tgv_hex_256.cgns`：16,777,216 个六面体，16,974,593 个
原始节点，CGNS 文件约 1.39 GiB。网格生成、周期面检查、原生 CGNS 读取
均成功。

高效模式分别以 64 和 32 个 MPI 进程试跑 `t=0`。两次都通过周期网格
预处理和对偶几何构建，但随后内存继续快速增长：64 进程试跑观察到约
361 GiB MPI 总 RSS，系统可用内存约 70 GiB；32 进程试跑观察到约
402 GiB 总 RSS，可用内存约 37 GiB。这些是安全中止时的观测值，
**不是完成计算所需的峰值**。两次均在重构完成前主动停止，以避免 OOM；
`t=8` 当时未启动。32 进程试跑日志位于
`data/out/NCFV/taylor_green_2d_rhs/hex256_efficient_t0.log`。

前五档网格的高效方法实际只接受最多 2 层节点环，但原配置预建 4 层。
将最大节点环改为 2 后，128³ 在 `t=0` 与 `t=8` 的全部五项误差指标均与
原配置逐位相同。以相同重构、物性和求积设置重新运行 256³ 高效方法：
32 个 MPI 进程、`MALLOC_ARENA_MAX=2`、内存安全线 96 GiB；`t=0`
与 `t=8` 均完整成功。两个时刻的 `L₂` 分别为
`3.74551010963642×10⁻⁵` 和 `3.11363127082752×10⁻⁵`，128→256 观测阶
分别为 `2.967736` 和 `2.988888`；耗时分别约 1631 秒和 1929 秒。
重构阶段观察到约 295 GiB MPI 总 RSS，系统可用内存约 136–153 GiB。

传统模式未直接启动：128³ 的传统几何已经保存 1,409,286,144 个体积求积项
和 150,994,944 个内部表面求积项。按当前数据结构，256³ 对应数量再增加
8 倍；仅这两类项的最低存储量约 399 GiB。128³ 传统试跑期间观察到约
93 GiB 的 MPI 进程总 RSS，按网格单元数外推约 740 GiB，高于本机
503 GiB 物理内存。该估计不代表一种优化后流式求积实现的需求。

因此，256³ 的**高效方法**在当前机器上可通过限制预备节点环安全运行；
当前**传统方法**仍不适合在本机直接尝试。两者的误差比较最高只到 128³。
