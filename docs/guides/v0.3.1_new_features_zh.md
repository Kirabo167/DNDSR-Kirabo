# DNDSR v0.3.1 新功能与迁移说明

本文说明从本项目原有基线 `v0.2.1` 升级到官方 `v0.3.1` 后新增或发生实质变化的功能，
并记录本项目自有的 ACM、ACMVariable 与 NCFV 模块所做的兼容适配。

> 版本身份：官方功能基线为 `v0.3.1`。由于本项目在 `v0.2.1` 之后还有 6 个自有提交，
> 集成后的源码是“`v0.3.1` 功能基线 + 本项目扩展”，而不是未修改的官方标签。
> 初始双父集成提交为 `783243c`；后续 fork 提交仍以 v0.3.1 为功能基线，
> 并使用 `0.3.1.postN+g<commit>` 形式的 PEP 440 后发布版本。

2026-10-09 的求解器入口和 cases 目录已经按类别、维度拆分；使用时请结合
[求解器拆分与迁移说明](solver_split_zh.md)。本文下方记录的是 v0.3.1 集成范围，
不能据此推断本地与当前上游的场解严格一致。

## 1. 功能概览

| 模块 | 主要变化 | 默认可用性 | 对现有模块的影响 |
|---|---|---|---|
| Euler / EulerEX | 多组分反应 Navier–Stokes、Cantera 热化学、化学源项与 Jacobian、组分扩散 | `DNDS_USE_CANTERA=ON` 时启用 | 非反应 Euler 模型保持可用 |
| Euler 状态与时间推进 | 新状态输入类型、物理量/无量纲转换、耦合源项、tau/Strang 分裂 | 按配置启用 | 旧数组状态仍按 `consSensible` 兼容解释 |
| RANS | SA、Wilcox、SST、RKE 的生产项或湍黏度上限可配置 | 默认值保持在配置对象中 | 本集成让 Wilcox 内核实际读取已传入的 `productionLimit` |
| Geom | 3D edge 流水线、周期 PBI、重排和分布式读取加固 | 默认启用 | 邻接接口要求显式传入 incidence 序号 |
| CFV / Solver | 周期自连接面、ILU 自边、重构 incidence 传递、ODE 分裂契约 | 默认启用 | 调用方不能再从 `face2cell` 猜测周期侧别 |
| DNDS | 环境变量读取、可选引用、统一输出目录、配置校验、版本生成 | 默认启用 | Serializer 默认格式由 JSON 改为 H5 |
| 工具与案例 | `eulerState`、常容反应轨迹、爆轰/火焰案例、周期波形网格生成器 | 按目标构建 | 新增 Cantera 依赖；网格脚本复用既有 CGNS 库 |
| ACM / ACMVariable | 保留原有常密度/变密度、BDF2、RANS 与 MPI 功能 | 按 `all_acm` 或具体目标构建 | 已适配新的周期 incidence 接口 |
| NCFV | 保留节点中心有限体积方法与 MPI I/O | 按 `all_ncfv_euler` 或具体目标构建 | 已适配新的 `gammaEq/gamma` 和组分基准能接口 |

## 2. Euler 多组分反应流

### 2.1 热化学与状态布局

- 新增 `ChemicalSource`，通过 Cantera 3.2 获取热力学性质、反应速率、混合平均输运系数、
  化学源项以及隐式求解所需的完整 Jacobian。
- 新增 `PhysicsProperties`，集中处理代码单位与 SI 单位转换、温度反演、比热、气体常数、
  声速、黏度、导热和扩散系数。
- 反应流状态保存 `Ns-1` 个独立组分密度 `rhoY`；最后一个组分由
  `rho - sum(rhoY)` 恢复，从而维持总密度约束。
- 总能量显式区分 sensible energy 与 composition base energy。
  压强闭合使用 `gammaEq`，声学速度使用由 `Cp/Cv` 得到的 gamma；二者在变组分状态下不能混用。

主要实现位于：

- `src/Euler/Chemistry/ChemicalSource.hpp`
- `src/Euler/Physics/PhysicsProperties.hpp`
- `src/Euler/SourceTermContributor.hpp`
- `src/Euler/Gas.hpp`

### 2.2 化学源项、扩散与数值通量

- EulerEX/EX3D 可在对流、黏性和化学反应之间进行耦合计算。
- 混合平均组分扩散包含 correction velocity，保证组分扩散通量之和为零；
  能量通量包含组分焓扩散项。
- reactive Roe 通量处理组分基准能跳跃；`Roe_M9` 从保留枚举变为可用实现，
  包含 H-correction 与 Harten–Yee 型耗散处理。
- 正性保持扩展到组分单纯形和 sensible internal energy，避免负组分、负内能或非法温度进入化学计算。

> `Roe_M9` 是 Riemann/耗散方案，不是 CFV 重构 limiter。
> 当前 Euler 求解器可选用该方案；NCFV 的独立配置校验仍明确拒绝
> `Roe_M9`，因此不能把 Euler 的支持范围直接外推到 NCFV。

### 2.3 v0.3.1 的状态修复

初始化和重启读取后会调用 cell-mean 状态修复：

1. 先用 `1e-30` 截断负值或极小的独立组分密度；
2. 当独立组分之和越界时，再整体按比例压回到 `rho * (1 - 1e-14)`；
3. 不改变密度、动量或总能量；
4. 检查有限值、正密度、正 sensible internal energy 和机理允许的最低温度；
5. 修复完成后刷新 ghost 数据。

化学源项在积分点只修复临时质量分数缓冲区。对流/扩散所运输的 `rhoY` 及其梯度不会被该临时投影覆盖，
避免在不同数值链路中悄悄改变守恒状态。

### 2.4 状态输入与源项时间耦合

`StateValue` 支持以下主要形式，并可使用物理单位后缀 `_phy`：

- `cons`
- `consSensible`
- `primRhoP`
- `primRhoT`
- `primTP`

旧版数组形式仍兼容，并按 `consSensible` 解释。反应流配置新增机理文件、输运模型、参考尺度、
基础温度、化学 CFL 缩放、cell temperature warm cache、化学松弛等控制。

时间耦合支持：

- 与流动 RHS/Jacobian 耦合；
- 实验性的 pseudo-time source splitting；
- 物理时间 Strang splitting。

Strang splitting 只用于 reactive EX 单步 ODE 路径，与 tau splitting 互斥，且不支持 `useImplicitPP`。

### 2.5 新应用与案例

- `eulerState`：检查各 Euler 模型的状态、单位换算和热化学一致性；
- `canteraConstVolTrajectory`：比较 DNDSR backward-Euler 常容轨迹与 Cantera 参考轨迹；
- `cantera_Test`：验证 Cantera 库、机理文件和数据目录；
- `cases/euler/2D/EX/`：新增预混、1D/2D 爆轰、H2/O2 机理及 schema；
- `scripts/reaction/` 与 `workspace/detonation*`、`workspace/flame1d`：提供参考计算和后处理证据。

## 3. RANS 可配置安全上限

v0.3.1 将若干原来写死在实现中的上限放入 typed config，并写入 Euler JSON schemas。

| 模型 | 配置项 | 默认值 | 作用 |
|---|---|---:|---|
| SA | `productionLimit` | `1e5` | 限制 SA 生产项；Orion 案例显式使用 `100` 保留旧行为 |
| Wilcox k-omega | `productionLimit` | `20` | 限制 k 方程生产项 `Pk` |
| Wilcox k-omega | `turbulentViscosityLimit` | `1e5` | 限制湍流黏度比 |
| SST | `productionLimit` | `20` | 限制 k 方程生产项 `Pk` |
| SST | `turbulentViscosityLimit` | `1e5` | 限制湍流黏度比 |
| realizable k-epsilon | `turbulentViscosityLimit` | `1e5` | 限制湍流黏度比 |

配置从具体 RANS 对象传入黏度、源项和黏性通量计算。官方 `v0.3.1` 已把
`KOmegaConfig` 传到 Wilcox 源项内核，但 k 方程的 `Pk` 限幅仍硬编码为 `20`；本集成把该常量
改为已传入的 `config.productionLimit`，使 JSON 配置真正改变计算结果。

## 4. Geom、CFV 与 Solver

### 4.1 周期面 incidence 语义

自周期面可能出现 `face2cell = (iCell, iCell)`，只比较 cell ID 无法判断当前访问的是面哪一侧。
相关 API 现在要求显式传递：

- `ic2f`：面在当前 `cell2face[iCell]` 行中的位置；
- `if2c`：当前单元在面的侧别，0 为 back/left，1 为 front/right。

该信息贯穿法向量、积分点坐标、相邻单元坐标、周期变换、重构和隐式矩阵装配。

### 4.2 网格与分布式处理

- 完善 3D `cell2edge`、`edge2node`、`edge2cell`、PBI、ghost 和 local/global 转换流水线；
- 重排注册表同步处理 edge 与周期信息，并加固 `ReorderLocalCells`/`ReorderEntities`；
- 分布式 H5 读取采用更稳健的 even split 与 ParMETIS 选择；
- CGNS 多 zone 节点默认使用 union-find 合并，并支持单边 `Abutting1to1`；
- 边界网格提取会跳过周期面；
- 修复周期自连接 ILU 边和转置矩阵乘的数据竞争。

多 zone 节点合并可能改变节点或单元编号。依赖固定编号的后处理脚本应改用 zone、坐标或持久 ID 匹配。

### 4.3 ODE 与输出

- ODE 接口新增 multistep 查询、fresh-start 重置和 source-splitting 契约；
- `nTimeStep = 0` 可执行只初始化/输出网格的流程；
- `meshOutAtInit` 可在求解开始时输出网格；
- 新增统一 `OutputDir`，减少各应用自行拼接路径的不一致。

## 5. DNDS、配置、I/O 与构建系统

- 新增 `EnvReader`、`OptionalRef` 和 `OutputDir`；
- typed config registry 支持嵌套 validation 与字段 schema；
- MPI 浮点类型改为标准 `MPI_FLOAT`/`MPI_DOUBLE`；
- `VERSION` 加 git describe 生成 PEP 440 版本：匹配发布标签后的 fork 提交使用
  `.postN+g<hash>`，向下一版本开发时使用 `.devN+g<hash>`；构建检查器检测
  HEAD 变化，并在下一次构建时触发自动重新配置；
- Cantera 成为可选编译能力，但 `DNDS_USE_CANTERA` 默认是 `ON`；
- Python/CI 基线更新到 Python 3.12，并增加 Cantera、HDF5、MPI 的一致构建流程；
- SerializerFactory 的默认输出格式从 JSON 改为 H5。

最后一项属于行为迁移：依赖“未指定格式时自动写 JSON”的调用必须显式选择 JSON，
或按新默认处理 `.h5` 输出。

## 6. 本项目自有模块的兼容适配

### 6.1 ACM 与 ACMVariable

原有 2D/3D、常密度/变密度、显式/隐式推进、BDF2 双时间步、RANS、MPI 和 I/O 接口及构建目标均予以保留。
适配内容包括：

- 所有 cell-centric 面循环传递真实的 `ic2f`；
- 法向量、周期坐标和相邻单元坐标使用显式 `if2c`；
- implicit diagonal、off-diagonal 与 LU-SGS coupling 按 `if2c` 选择左右 Jacobian；
- self-periodic 的 opposite-side coupling 折入本地 diagonal，完整算子不再把同一项重复当作 off-diagonal；
- 不再用 `face2cell[0] == iCell` 推断自周期面的方向。

这些改动在修复编译接口的同时，旨在保持双周期/自连接网格上的左右侧数值语义。

### 6.2 NCFV

节点中心有限体积模块继续使用定比热非反应理想气体。适配新的 Euler Gas API 时：

- `gammaEq` 与声学 gamma 均传入原有 `_physics.gamma`；
- conservative-to-primitive gradient 显式传入空的组分基准能向量；
- viscous flux 同时传入 `gammaEq` 与 gamma。

因此 NCFV 的原物理模型不变，同时可以与扩展后的多组分 Gas API 共存。

### 6.3 验收矩阵

ACM 与 NCFV 测试沿用 `DNDS_TEST_TIMEOUT` 和按 MPI rank 缩放的统一超时策略，
并继续注册到 `all_unit_tests`。完整集成验收包括：

- ACM/ACMVariable 目标与单元测试；
- NCFV 目标与单元、MPI、I/O 测试；
- DNDS、Geom、CFV、Euler、Solver 的完整 C++ CTest；
- pybind11 重新构建并安装后的 Python 测试；
- Cantera ON/OFF 两种配置；
- reactive、RANS limit 和周期 self-face 的重点回归。

### 6.4 本次集成验证结果

本次合并在 Release 配置下完成了以下实际验证：

| 验证项 | 结果 |
|---|---:|
| `DNDS_USE_CANTERA=OFF`，全部 CTest 条目（100 个 C++/MPI + 2 个 pytest suite） | `102/102` 通过 |
| 重新构建并安装四个 pybind11 模块后的完整 Python 测试 | `49` 通过，`1` 跳过 |
| `DNDS_USE_CANTERA=ON`，全部 CPU C++/MPI CTest | `108/108` 通过 |

| ACM/ACMVariable 回归（包含一单元双周期隐式算子专项测试） | `13/13` 通过 |

## 7. 构建和运行

### 7.1 外部依赖

```bash
git submodule update --init --recursive
python3.12 -m venv venv
source venv/bin/activate
pip install -r external/cfd_externals/requirements.txt

# 下载并解压 header-only 依赖（Eigen、Boost、CGAL、fmt、pybind11 等）
bash scripts/install_headeronly_deps.sh

cd external/cfd_externals
CC=mpicc CXX=mpicxx python cfd_externals_build.py
cd ../..
bash scripts/install_python_deps.sh
```

### 7.2 测试网格

主仓库有意忽略 `data/mesh/*`；完整 Geom、CFV 和 Euler 测试所需网格由官方 CI 从
`harryzhou2000/cfd_meshes` 单独取得。为避免测试基准随外部仓库 `main` 漂移，建议固定到
本次验证使用的提交 `a5bba6f076ede1f9ba82219a8c4613b4481d3c7d`：

```bash
git clone --no-checkout --filter=blob:none \
  https://github.com/harryzhou2000/cfd_meshes.git /tmp/cfd_meshes
git -C /tmp/cfd_meshes fetch --depth=1 origin \
  a5bba6f076ede1f9ba82219a8c4613b4481d3c7d
git -C /tmp/cfd_meshes status --short
git -C /tmp/cfd_meshes checkout --detach \
  a5bba6f076ede1f9ba82219a8c4613b4481d3c7d
cp -n /tmp/cfd_meshes/data/mesh/* data/mesh/
```

`cp -n` 不覆盖本地已有的同名网格；如需严格复现实次验证，请先单独核对已有文件的
来源或校验和。缺少这些文件时，相关测试会在 CGNS 打开阶段失败，不能把该结果解释为
数值算法回归。

### 7.3 带反应流构建

```bash
CC=mpicc CXX=mpicxx cmake --preset reactive-test
cmake --build --preset reactive -j16
ctest --preset reactive

# 只复跑 8 项化学/反应流专项测试：
ctest --preset reactive-focused
```

运行反应流前设置机理搜索路径；构建系统找到的数据目录也会写入相关目标：

```bash
export DNDS_MECH_PATH=/path/to/mechanisms
export CANTERA_DATA=/path/to/cantera/data
```

### 7.4 不带 Cantera 的兼容构建

```bash
CC=mpicc CXX=mpicxx cmake -S . -B build-no-chem \
  -DDNDS_USE_CANTERA=OFF -DDNDS_BUILD_TESTS=ON
cmake --build build-no-chem -t all_unit_tests -j16
ctest --test-dir build-no-chem -LE python --output-on-failure
```

非反应 Euler、Geom、CFV、Solver、ACM、ACMVariable 和 NCFV 均应在该模式下工作。

运行完整 Python 回归前必须重新构建并安装四个扩展模块：

```bash
cmake --build build-no-chem \
  -t dnds_pybind11 geom_pybind11 cfv_pybind11 eulerP_pybind11 -j16
cmake --install build-no-chem --component py
PYTHONPATH="$PWD/python" venv/bin/python -m pytest test/
```

## 8. 已知范围与限制

- reactive CFD 只在 Euler EX/EX3D CPU 路径提供；EulerP/CUDA 尚无反应流实现；
- 使用反应流必须构建 Cantera，并保证 mechanism 与 data path 可访问；
- Strang splitting 有第 2.4 节所列组合限制；
- CGNS 多 zone union-find 合并可能改变实体编号；
- 旧版未显式指定 Serializer 格式的调用需要检查 H5 默认值迁移；
- `.opencode/skills`、反应流 workspace 和图片属于开发工具与验证资产，不是运行时 solver API。
